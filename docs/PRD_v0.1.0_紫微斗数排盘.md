## 二、项目定位

### 2.1 一句话定位

输入出生年月日时（农历/公历），自动排出紫微斗数命盘——十二宫 + 十四主星 + 六吉六煞辅星 + 四化 + 命身宫 + 五行局 + 大限，纯本地单文件 Web 工具，零账号零依赖。

### 2.2 为什么做（对齐邦顺战略）

| 维度 | 说明 |
|------|------|
| 战略价值 | 生命算法体系以命理为解码工具；八字排盘已成熟（v0.25.0），紫微斗数是同一体系的姊妹工具，补足「星曜系统」视角 |
| 发布优先 | 单文件 HTML + GitHub Pages，一次发布即可对外分享，符合「在创作中搞钱」模式 |
| 复用经验 | 完整复用八字项目的文档体系、开发流程、发布链路、单文件架构经验，避免重复踩坑 |
| 产品差异 | 八字看「气数流变」（四柱十神大运流年）；紫微斗数看「星曜格局 + 十二宫人事领域」，两者互补 |

### 2.3 目标用户与场景

- **邦顺本人**：生命算法体系内容创作时快速排盘取盘、作为案例底稿
- **自在班学员**：看自己的星盘结构，辅助理解先天配置（自我即受众，无需用户调研）
- **典型使用路径**：打开工具 → 输入出生信息 → 得命盘 → 截图/讲解/存档

### 2.4 发布形态（v1 确定）

| 形态 | 说明 |
|------|------|
| 单文件 HTML | 零构建，双击即用（对齐八字 ADR-1 单文件策略） |
| Clacky 侧栏扩展 | 开发期经 `localhost:7070` 内测，最终挂侧栏（对齐八字 launcher/paipan 面板模式） |
| GitHub Pages | 公测/正式版线上发布（对齐八字 bangshun2025.github.io 模式） |

## 九、开发流程与里程碑建议（对齐 DEVELOPMENT.md）

> 迭代式开发：**版本 = N 个功能迭代的累积**，每个功能迭代走 PRD → 架构 → 开发+测试 → 内测 → 邦顺看一眼。

### 9.1 v0.1.0 建议功能迭代拆分（供 Leader 派活参考）

| 迭代 | 功能 | 验收要点 | 依赖 |
|------|------|---------|------|
| F1 | 输入 + 历法转换（公农历 1800-2200） | 转换正确性锚点 AR04 | 历法数据源 |
| F2 | 真太阳时修正 | AC05 + 跨时辰边界 | F1 |
| F3 | 命宫身宫 + 十二宫 + 五行局 | AR02 + AC10 | F1 |
| F4 | 紫微星定位 + 十四主星安星 | AR03 + AR01 | F3 |
| F5 | 六吉六煞 + 四化 | AR01 逐星比对 | F4 |
| F6 | 大限 + 盘面渲染完整 | AC01/AC06-09 + ?test 断言 | F3-F5 |

> 每个迭代独立产出功能级 PRD（由产品经理在迭代启动时补写，对齐八字 PRD_v0.X.X 模式）。

### 9.2 角色交接链（对齐宪法）

```
产品经理(本 PRD) ──→ 架构师（ALGORITHM.md + ADR + 版本注释）
    → 编程师 ↔ 测试师（高频结对 + ?test=1 断言）
    → 测试师 L2 功能验证 → 发布师内测部署 → Leader → 邦顺「看一眼」
    → 全量回归 → 公测 → 正式版 → 归档整理 → 复盘
```
