## 一、定位与命名

**名称：生命算法的紫微。**

它不是紫微斗数的一个新流派，而是《生命算法》体系下的一个模块。与八字模块**共用内核**，只在符号集上不同。

|  | 八字模块 | 紫微模块 |
| --- | --- | --- |
| 关系层内核 | 生克比（五类，含方向） | **同一内核** |
| 权限层内核 | 旺相休囚死（月令为我） | **同一内核** |
| 符号集 | 十干十二支、四柱 | 十四主星、十二宫 |

因此本规范**不建立独立的公理体系**：ZW- 系列公理只描述紫微符号集的特有约束，其关系层与权限层直接调用八字模块。

**一句话定义**：紫微是**八字的一个投影，加上一个月相量**。

## 三、历法层

### 3.1 主轴：节气干支轴（唯一日历轴）

| 单位 | 界限 | 驱动 |
| --- | --- | --- |
| 年 | **立春**，交节精确到分钟 | 四化、年干系、年支系、将前岁前、小限 |
| 月 | **以「节」为界**（立春、惊蛰、清明……），恒十二个 | 命宫、身宫、辅弼刑姚、斗君、月令 |
| 日 | 连续六十循环 | 解盘层（待议）；**排盘层不用** |
| 时 | 真太阳时校正后的时辰 | 命宫、身宫、昌曲劫空台辅封诰 |

### 3.2 朔望轴：退化为单一标量

`lunarDayIndex ∈ 1–30`，**合法用途穷举为二，其余一律报错**：

1. **安星族**：安紫微 `q=ceil(d/m)`、三台、八座、恩光、天贵
2. **太阴月相**：层 E 日月光度

**为何不改用「节气月内第几日」以彻底消灭朔望轴**：传世安星表定义域为 1–30，而节气月长 29.4–31.5 天不等；更要紧的是五局锚点（水二局初一在丑、木三辰、金四亥、土五午、火六酉）全部依赖朔望日序，换掉即失去全部校验基准。**ZW-A7 在此处有效，日序必须保留朔望来源。**

### 3.3 已消失的四项

| 原配置项 | 状态 | 消失原因 |
| --- | --- | --- |
| 闰月归属（前 15 日／后 15 日） | **删除** | 闰月规则是「十三个月塞进十二宫」留下的补丁；月改节气后一年恒十二个月，补丁失去对象 |
| 中气校正月 | **删除** | 体系已裁定「不以中气按次月推算，而以节来推算」 |
| 排盘轴年界（初一／立春） | **删除** | 已裁定立春 |
| 生月定义（农历／节气） | **删除** | 已裁定节气月 |

### 3.4 代价声明（不可粉饰）

节的位置在农历月内近似均匀分布，故**约 50% 的人，节气月与农历月取值不同 → 生月数不同 → 命宫位移 → 十二宫整体错位**。

1. 这不是缺陷，是定义变更。输出必须标注 `monthAxis = solarTerm`。
2. **「用传世案例验证引擎」这条路彻底关闭**。古籍与今人案例均基于农历月盘，本规范只能靠自建实测案例库积累验证。
3. 与弃用庙旺表是同方向的第二步：体系内部自洽，代价是与外部完全脱钩。

## 四、排盘层（十七步，全为纯函数）

索引基准：**寅=0 顺行**（寅0 卯1 辰2 巳3 午4 未5 申6 酉7 戌8 亥9 子10 丑11）；一切取模用 `index = ((n % 12) + 12) % 12`。

| 步 | 内容 | 算法 |
| --- | --- | --- |
| ① | 十二宫 | 命宫 `=(月序−1) − 时支序`；身宫 `=(月序−1) + 时支序`；宫名 `[k] = (命宫 − k) mod 12` 逆行 |
| ② | 宫干 | 五虎遁定寅宫干：甲己→丙、乙庚→戊、丙辛→庚、丁壬→壬、戊癸→甲，顺排 |
| ③ | 五行局 | 命宫干支 → 纳音 → 水2／木3／金4／土5／火6 |
| ④ | 安紫微 | `q=ceil(d/m); r=m*q−d`；r=0 → `q−1`；r 偶 → `(q−1)+r`；r 奇 → `(q−1)−r`；mod 12 |
| ⑤ | 天府＋十四主星 | 天府 `=(12 − 紫微index) mod 12`；紫微系偏移 天机−1·太阳−3·武曲−4·天同−5·廉贞−8；天府系偏移 太阴+1·贪狼+2·巨门+3·天相+4·天梁+5·七杀+6·破军+10 |
| ⑥ | 年干系 | 禄存＝十干临官位（甲寅乙卯丙巳丁午戊巳己午庚申辛酉壬亥癸子）；擎羊＝禄存+1；陀罗＝禄存−1；天魁天钺＝天乙贵人表 |
| ⑦ | 年支系 | 火星·铃星（三合起例）；天马＝三合局长生对宫；红鸾＝卯起子年逆数至年支；天喜＝红鸾+6 |
| ⑧ | 月系 | 左辅 辰起正月顺／右弼 戌起正月逆；天刑 酉起正月顺／天姚 丑起正月顺 |

## 五、解盘层

### 5.1 层 A｜关系层（生成器，纯函数）

`R = rel(S, G)`，S＝星曜五行，G＝宫支五行。五类穷举，**无优劣次序**：

| 条件 | 关系 | 语义 |
| --- | --- | --- |
| S = G | **本位** | 无摩擦，也无锻炼 |
| G 生 S | **受养** | 环境供养职能 |
| S 生 G | **付出** | 职能反哺环境 |
| S 克 G | **支配** | 职能要改造环境 |
| G 克 S | **受制** | 环境压制职能 |

### 5.2 层 D｜权限层

权限函数 `A(X, M)`，M＝月令五行。**须调用八字模块，紫微侧禁止另行实现。**

| X 与 M 的关系 | 档 | 序数 | 权限语义 |
| --- | --- | --- | --- |
| X = M（当令） | 旺 | 5 | 全权负责 |
| M 生 X | 相 | 4 | 受器重的副手 |
| X 生 M | 休 | 3 | 已交权、退居后台 |
| X 克 M | 囚 | 2 | 被关小黑屋 |
| M 克 X | 死 | 1 | 不允许动 |

**取气法已裁定：季月属土**（辰未戌丑月土旺）。

### 5.3 组合规则（按关系类分派，禁止统一公式）

```
本位：  out = A_S                     ← 看自身
        ≥4 本性全权直出 | =3 可显但无势 | ≤2 想直出而不被允许

受养：  out = A_G                     ← 看给方（宫）
        ≥4 真供养 | =3 勉力可给 | ≤2 环境自身匮乏 → 虚养

付出：  out = A_S                     ← 看给方（星）
        ≥4 有余力，付出有功 | =3 尚可 | ≤2 无力硬给 → 枯耗

支配：  Δ = A_S − A_G                 ← 看双方之差
        >0 克得动 | =0 拉锯 | <0 克不动 → 反伤星

受制：  Δ = A_G − A_S
        >0 确实受制 | =0 抗衡 | <0 宫克不动 → 星不受制
```

**三条规则的依据（均为八字既有实践的直接转写，非新造）**：

- 比类看自身：比肩须自身得令方论发挥
- 生类看给方：**印衰不能生身**；食伤须日主有力方生得出
- 克类看差值：**旺木不受弱金克，此即「囚」**

> **推论（定理）**：为何只有「克」需要力量比较？因为只有克是对抗性的——生是转移（只需给方有货），比是无转移（只需自身有权），**唯独克有输赢，故唯独克需要比**。

**克类用差值而非绝对分**，使全盘同向偏移自动抵消，保全命盘结构。

### 5.4 层 E｜日月光度层（唯一真天文层）

**仅适用太阳、太阴。** 依据真天文量，不经五行、不经月令、不经生克。

| 对象 | 光度函数 | 输入 | 天文含义 |
| --- | --- | --- | --- |
| 太阳 | `L☉ = f(宫位, 节气)` | 宫位读作一日十二时辰的天球位置（午＝正中、子＝夜半）× 节气读作太阳赤纬（夏高冬低） | 视高度角 |
| 太阴 | `L☽ = g(宫位, 朔望日序)` | 宫位（昼夜位置）× 月相（初一朔→暗、十五望→满） | 视亮度 |

> 这是体系内唯一使用真实天文量的地方，且两轴在此合流：**太阳用节气（赤纬），太阴用朔望（月相）**。这是双轴分离的正当性证明。

**铁律**：层 E 只接受时辰位置、太阳赤纬、月相三类输入；传入任何五行或月令参数即报错。

## 附录 B｜可复用的通用判据

以下判据由紫微研究中析出，**适用于整个生命算法体系，不限紫微**：

1. **移植成功的条件**：借入物只保留结构，其语义、判据、运算与合法性基础全部由接收方公理重写。
2. **伪精度原则**：解读层的分辨率不得高于数据层的可靠度，超出部分是伪精度。底层无损存最细粒度，粒度压缩只发生在读取端。
3. **可操作性检验**：若找不到一句「只对 X 档成立而对 Y 档不成立、且可被现实反证」的断言，则 X／Y 的区分在判读端零信息量。加副词的同一句话不算。
4. **单向 vs 双向误差判据**：偏差单向可重标定 → 表由规则生成，仅命名混乱；偏差**双向且跨类** → 表不是该规则生成的，重命名无法复原。
5. **禁止用解释器重算并覆盖传承数据**：误差双向跨类时重算属不可逆信息破坏。
6. **可推导性与多家收敛是两种不同性质的可信度，不可换算**，故算法层与数据层必须并列，不可合并。
7. **静态表不能承载时变量**：不含时间维度的查找表装不下随时间变化的量；表现为在时间敏感项上出现不可调和的流派分歧。
8. **粒度匹配律**：力量参照系的时间粒度须匹配该体系所回答问题的时间粒度（八字—月／奇门—时／应期—日）。
9. **跨道冒充检验**：取一结论，列出其全部输入。若输入全属 A 道而结论属 B 道，则该结论为冒充，其误差**不可通过增补数据或重命名修复**，只能换用有 B 道原料的体系。**症状三联：必然降维、必然静态化、必然无法校准；三症齐现即可判定。**
10. **基准资格审查**：拿 X 验证 Y 之前，先问 X 凭什么算标准答案。若 X 不可推导、内部不一致、且成因是事后合理化，则 X 与 Y 的偏离度测的是 X 的偏差，不是 Y 的错误。

8. 「紫微是土、寅是木，木克土该落陷，全天下的排盘软件却都显示——庙」
9. 「同一套五行关系，第三名和第四名的次序是反的。**术数体系的分歧，多半不在结论，在参照系。**」
10. 「**庙旺表的问题不是不准，是降维。**」
11. 「它想克，但克不动。克不动的结果不是相安无事，是反伤。」
12. 「**一张不含时间的表，装不下一个随时间变的东西。**」
13. 「紫微没有『月令』这一层。可它的母体七政四余里明明写着『尔知有令星乎，春木夏火秋金冬水季月属土』。**紫微在衍生的路上，把时间丢了。**」
14. 「紫微算庙陷，手里只有两样东西：星的名字，和宫的位置。这两样都是地上的东西。可『有没有力量』，从来是天上的事。」
15. 「我把庙旺表弃用了。**一张一百六十八格、要翻五家古籍、各家还对不上的表，删掉之后，整个排盘引擎反而能算了。**因为它本来就不该是一张表——星是职能，宫是环境，月令是发权限的机构。」
16. 「学紫微都要背一条规矩：闰月怎么算？争了几百年。**后来我发现这条规矩根本不是术数原理，它是个补丁。**十三个月塞不进十二个宫，才需要有人裁『多出来那个月归谁』。把月份改成按节气走，补丁就自己掉了——不是解决了闰月问题，是闰月这个问题不存在了。」
17. 「**不是紫微和八字是两门学问。是它们本来跑在同一个内核上，只是加载了不同的符号。**」
