### 2.2 版本演进规则（SemVer + 八字两段式）

| 环节 | 动作 | push？ | 触发条件 |
|------|------|--------|---------|
| 内测迭代 | patch+1（v0.1.0 → v0.1.1 → …）于全部头注释 + CHANGELOG 条目，git commit | ❌ 不 push | 内测发现问题并修复（对应八字「发布本地」） |
| 公测 | push origin main（GitHub Pages 自动部署当前版本） | ✅ push main | Leader 授权公测留痕（v0.20.0 八字教训：禁止跳过公测直接上线） |
| 正式 | annotated tag `vX.Y.Z` + push --tags | ✅ push --tags | 公测验证通过 + Leader/用户授权正式发布 |

- 版本号判定：新功能 MINOR+1；修复 PATCH+1；破坏性/架构级 MAJOR+1（v0.x 阶段以 0.MINOR.PATCH 递增）。
- **当前状态**：v0.1.0 核心链路 + UI 渲染已完成（?test=1 自检 88 条通过）→ 首轮真实发布即 **v0.1.0 内测/公测**，验收通过后正式 tag v0.1.0。
- 防呆（移植八字 skill）：tag 名 == 当前头注释版本号时才允许打；若最新 tag 已等于当前版本 → 阻止重复发布。

## 三、GitHub Pages 发布步骤（tag → CHANGELOG → push → 部署）

### 3.1 阶段 0：仓库初始化（一次性，授权后执行）

```bash
cd /Users/feng/人生资产/10-开发项目/软件-紫微斗数/运行
git init
git add .gitignore  # 先落安全模板（见 §五）
git commit -m "v0.1.0: 运行目录初始化（Phase 0）"
git remote add origin git@github.com:bangshun2025/ziwei-paipan.git
git push -u origin main
# GitHub 网页端：Settings → Pages → Deploy from branch: main / root
```

### 3.2 阶段 1：内测（本地发布，不 push）

1. `bash scripts/check-release.sh` 全绿（版本一致性 + JS 语法 + 结构 id + 加载顺序）
2. 浏览器打开 `index.html?test=1` → 88 条断言 **0 FAIL**（红线）
3. 锚点回归：test/anchors a01~a12 对齐（正式验收轨，Leader 协调测试师）
4. bump 版本号：所有头注释同步 + CHANGELOG 条目 + SYSTEM.md 版本表（三处一致）
5. `git add` 明确清单（禁用 `git add -A`）→ `git commit -m "vX.Y.Z: <30字摘要>"`
6. 本地留痕即可，**不 push**（内测与公测 remote 分离防呆；八字红线：禁止内测误推公测仓库）

### 3.3 阶段 2：公测（GitHub Pages）

```bash
bash scripts/publish-online.sh --exec --tag-msg "<一句话标题>"   # 见 §四，或手工：
git push origin main
# 验证：curl -sI https://bangshun2025.github.io/ziwei-paipan/ → 200 且头注释为新版本
```

### 3.4 阶段 3：正式（tag + 留痕）

```bash
git tag -a v0.1.0 -m "v0.1.0: <一句话标题>"    # annotated tag（非 lightweight）
git push origin main --tags
```

### 3.5 部署验证与已知坑（移植八字经验）

- push 后 GitHub Actions 会跑 `pages build and deployment`，1-2 分钟生效。
- **Pages build 偶发不触发**（八字 2026-08-08 / 2026-08-29 两度实测）：若 push 后线上停留旧版，检查
  `curl -s "https://api.github.com/repos/bangshun2025/ziwei-paipan/actions/runs?per_page=5"`，
  无本次 SHA 的 pages build run → 推空 commit 强制触发：
  `git commit --allow-empty -m "ci: 触发 GitHub Pages 重新部署" && git push origin main`。
- 验证线上版本：`curl -s https://bangshun2025.github.io/ziwei-paipan/ | head -3` 应见新版本注释。

## 四、发布脚手架（本次产出，位于运行目录 scripts/ 与发布师目录）

| 文件 | 职责 | 用法 |
|------|------|------|
| `scripts/check-release.sh` | 发布前静态校验（红线防线，移植八字事故防线） | `bash scripts/check-release.sh`（支持传目录参数） |
| `scripts/publish-online.sh` | 线上发布脚本：前置检查 → CHANGELOG → tag → push → 部署验证 | 默认 dry-run；`--exec --tag-msg "<标题>"` 真执行 |
| `.gitignore` | 安全防呆（备份/密钥类文件禁入库，八字 v0.24.0 教训） | git init 前落位 |
| `../紫微斗数·档案/v0.1.0_紫微斗数排盘/5-发布师/发布链路方案_v0.1.0.md` | 本方案（归档副本，运行内副本 docs/） | — |

> 真实发布时的 RELEASE 报告用 `docs/_TEMPLATE/RELEASE.md` 模板，产出后归档到
> `../紫微斗数·档案/<版本>/5-发布师/` 并在运行目录 docs/ 留部署报告（对齐八字 docs/部署报告-vX.Y.Z.md）。

### 4.1 check-release.sh 校验项（紫微斗数适配版）

1. 版本一致性：index.html 提取版本号 → 与 js×4、css、CHANGELOG 最新条目、SYSTEM.md 当前版本逐一比对
2. JS 语法：`node --check` constants/algorithm/render/main
3. 结构红线：index.html 关键 id 全部存在 + script 加载顺序 constants→algorithm→render→main
4. 引用完整性：index.html 引用的 js/css 文件真实存在

> 与八字差异：八字三文件（index/standalone/standalone-split）互相内联比对，紫微为**单入口 + 外链多文件**，
> 无内联单体，故去掉「模块段一致性」，改为「多文件版本号一致性」。

### 4.2 publish-online.sh 防呆红线（移植八字 skill）

- 前置必须通过：check-release.sh 全绿 + ?test=1 0 FAIL（脚本打印提示，人工确认项）
- git 仓库存在；无未提交改动（或 CHANGELOG 已含当前版本 → 自动补 commit，对齐八字「发布本地已执行但未 commit」处理）
- 当前版本 == 最新 tag → 阻止重复发布
- 选择性 git add，敏感文件扫描（password/secret/service_role/.bak/密码 出现在 staged → 拒绝）
- 默认 **dry-run**（只打印将执行动作），`--exec` 才真正 push/tag（八字两段式：正式发布需 Leader/用户授权后执行）
