## 二、亮点与问题

### 亮点

1. **iztro 双轨验证机制一步到位**：v0.1.0 从首版就建立了「iztro@2.6.0 权威实测锚点 + ALGORITHM 宪法」双轨，12 盘全字段快照把算法正确性变成可回归的硬断言——这是八字早期缺失、后期补课才有的资产，紫微起步即具备。
2. **P1 系统性错误被自动化捕获**：六辅星起宫常量错误 12 盘全中，锚点回归 88 条宫级断言批量失败，说明锚点覆盖设计有效（若只靠 ?test=1 数量自检会漏——教训见下）。
3. **宪法勘误流程规范**：发现公式与 §1.1 地支表自相矛盾后，走「修订说明 + 裁决 + 改常量清单」而非直接改代码；口径裁决（P2-2 展示/安星分离）有据可依且与 iztro 基准一致。
4. **发布脚手架提前就位**：未发布先备好 check-release.sh / publish-online.sh / 发布链路方案 / .gitignore 安全规则，正式发布时零临场设计。

### 问题

1. **ALGORITHM.md 首稿公式与坐标表自相矛盾**（P1 根因）：§10.2/§10.3 公式数值（辰=5、戌=11、地空地劫亥=9）与 §1.1 地支表（辰4…戌10…亥11）不一致，导致 constants.js 六常量照抄出错。宪法草稿缺「公式 ↔ 坐标表一致性」自检。
2. **?test=1 内嵌自检存在覆盖盲区**：只校验辅星数量（14 颗）不校验落宫，故首轮 82 条全绿仍未发现 P1——「数量自检」≠「位置自检」，自检设计需按断言维度审计。
3. **口径决策依赖后期裁决**：晚子时农历文本、闰月 mUse、早子时语义等关键口径在实现后/验收期才定稿（D-1~D-7、修订说明 P2-2），前期 PRD/ALGORITHM 未冻结展示层口径。
4. **报告数字口径漂移**：QA 报告/check-release.sh/发布链路方案多处写「82 条自检」，实际运行时为 88 条（循环展开），验收后由 TEST_全量测评手册 v1.0 勘误统一为 88——文档间数字需单点权威（SYSTEM.md）并同步。
5. **遗留观察项未清零**：辅星宫内顺序与 iztro 约 20 处不一致、a08/a12 mutagenMap 登记缺漏、a06/a10 需文墨天机人工抽核——均不阻断但需下版本承接。
